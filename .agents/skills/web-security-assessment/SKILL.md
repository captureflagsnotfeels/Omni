# Web penetration testing

Confirm target/scope, accounts/roles, prohibited actions, rate limits, and success criteria. Map hosts, routes, methods, parameters, technologies, APIs, trust boundaries, and authentication/session flows using passive evidence and targeted requests.

Prioritize authorization (object/function/tenant), authentication and recovery, session/cookie/token handling, server-side input handling, injection classes, request forgery, file upload/download/path handling, deserialization/template behavior, cache/proxy behavior, CORS, race/state logic, and exposed secrets/configuration.

For each lead record request, response, identity, state, prerequisite, expected secure behavior, observed deviation, impact, and minimal reproducible proof. Compare roles and objects systematically. A scanner/version finding is a hypothesis until the live behavior and prerequisites are verified. Avoid destructive payloads and excessive traffic; use unique harmless markers. Report exact reproduction, evidence, boundary crossed, impact, confidence, and remediation. In CTF mode continue toward the objective and explain the working chain.
